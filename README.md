# Video Gallery

Instagram の投稿・リールなどを URL で登録して一覧表示する、ビルド不要の静的サイト。
GitHub Pages にそのまま置ける（`index.html` / `style.css` / `app.js` / `data/videos.json` だけ）。

ローカル確認：

```bash
npx --yes http-server web-site-test/video-gallery -p 8160 -c-1
```

`.claude/launch.json` に `video-gallery`（ポート 8160）として登録済み。

---

## 機能

**登録・編集**

- URL を貼るとプラットフォームを自動判定し、フォーム内にライブプレビューを表示
- タイトル / 説明（改行可）/ タグ / 公開日 / 評価（★0〜5）/ サムネイル URL / お気に入り
- 同じ URL が既に登録されていれば警告
- 複数 URL を一括貼り付けして追加（メニュー →「URL をまとめて追加」）
- 編集・複製・削除。削除はトーストの「元に戻す」で復帰（8秒以内）

**表示**

- グリッド / リスト / コンパクトの 3 表示
- サムネイル状態はカードの高さを揃え、再生を押した時点でその動画本来の縦横比に切り替わる
- 埋め込みはタップして初めて読み込む（一覧を開いた時点では画像だけなので軽い）
- **再生は常に 1 つだけ。** 別のカードを再生すると、前のものは自動で止まる
- 拡大表示（ライトボックス）。矢印キーで前後の動画へ移動
- ダークモード（OS 設定に追従、手動切り替えも可）

**絞り込み・並び替え**

- 検索（タイトル・説明・タグ・URL を横断）
- タグ絞り込み（複数指定は AND）、プラットフォーム絞り込み、お気に入りのみ
- 並び順：手動 / 追加日 / 公開日 / タイトル / 評価 / ランダム
- **手動並び替え**を選ぶとカードをドラッグして順序を入れ替えられる

**一括操作**

- 選択モードで複数選択 → お気に入り切替 / タグ追加 / まとめて削除

**データ**

- **GitHub 連携**：追加・編集・削除・並び替えをそのまま `data/videos.json` にコミット（下記参照）
- JSON の書き出し・読み込み（ファイルをページにドラッグ＆ドロップでも読み込める）
- 読み込み時は「置き換え」か「追記」（URL 重複はスキップ）を選択
- クリップボードへ JSON をコピー（GitHub の Web エディタに貼る用）
- PWA としてインストール可、オフライン閲覧対応

**キーボード**

`N` 追加 / `/` 検索 / `G` `L` `C` 表示切替 / `F` お気に入り / `S` 選択モード / `?` ヘルプ / `Esc` 閉じる

## 再生方法は 2 通り

項目には **動画ファイル**と**元の投稿 URL** のどちらか（または両方）を登録できます。
両方あるときは**動画ファイルが優先**され、埋め込みは使われません。

| | 再生場所 | Instagram に触れるか |
|---|---|---|
| 動画ファイル（`videoSrc`） | ページ内の `<video>` | 触れない |
| 元の投稿 URL のみ | 埋め込み iframe | 埋め込み経由で触れる |

### 同時に再生されないようにする仕組み

**プレイヤーはページ内に常に 1 つしか置きません。** 別のカードを再生すると、前のカードの
`<video>` や `<iframe>` を DOM から取り外し、カバー画像＋再生ボタンの状態に戻します。

埋め込みはクロスオリジンなので、外側から「止めろ」と指示することができません。
確実に音を止める手段は取り外すことだけなので、Instagram・YouTube・TikTok・自前の動画ファイルの
どれであっても同じ扱いにしています。取り外してもカバー画像は残るので、見た目は元に戻るだけです。

保険として、`play` イベントをキャプチャで拾って他の `<video>` を一時停止する処理も入れています
（ネイティブの再生ボタンや拡大表示から直接再生された場合に備えたもの）。

> この制約があるため、以前あった「カードで埋め込みを自動読み込み」の設定は廃止しました。
> 複数のプレイヤーを同時に載せると、埋め込みの中身を操作できない以上、
> 1 つずつ再生する約束を守れなくなるためです。

### カード表示のきまり

- **カードは常に 9:16。** 中身の縦横比がこれと違っても切り取らず、`object-fit: contain` で
  全体が見えるように収めます（16:9 の YouTube なら上下に余白が出る）。
- 拡大表示（ライトボックス）でも本来の縦横比のまま、画面内に全体が収まります。

### Instagram のカバー画像は自分のリポジトリに取り込む

Instagram の CDN は画像に **`cross-origin-resource-policy: same-origin`** を付けて返します。
これは「他サイトからこの画像を読み込ませない」という指示で、ブラウザがこれを守るため、
**`<img src="https://...cdninstagram.com/...">` は必ず失敗します。** referrerpolicy を
どう変えても回避できません（curl では取得できてしまうので紛らわしい）。

そこで、**GitHub Actions がサーバー側でカバーを取得して `covers/` に commit** します。
サーバー側にはこの制約が効きません。

| | |
|---|---|
| ワークフロー | `.github/workflows/fetch-covers.yml` |
| スクリプト | `scripts/fetch-covers.mjs` |
| 実行タイミング | `data/videos.json` の更新時（＋毎日 06:17 JST の保険、手動実行も可） |
| 保存先 | `covers/<ショートコード>.jpg` |

動画を追加して同期すると、**約2分半後**にカバーが取り込まれ、さらに Pages の再ビルドを経て
表示されます。**追加直後はプレースホルダのままなので、少し待ってから再読み込みしてください。**

### まとめ待ちの仕組み

同期のたびに毎回コミットすると、`動画一覧を更新` と `カバー画像を取得` が交互に積み重なって
履歴が倍に膨らみます。これを避けるため、ジョブの先頭で 150 秒待ってから処理を始めます。

- 待機中に次の同期が来ると、待っているジョブは打ち切られ、新しいジョブが待ち直す
- 最後の同期から 150 秒経ったときだけ実際に取得・コミットする
- スクリプトは未取得のカバーを毎回すべて処理するので、打ち切られても取りこぼさない

結果として、動画を続けて追加しても**カバーのコミットは最後の1つだけ**になります。
`concurrency.cancel-in-progress: true` と、checkout より前に置いた `sleep` の組み合わせで
実現しています（待ってから checkout するので、待機中に増えた分もまとめて処理できます）。

取得済みのファイルは再取得しません。取り直したいときは `covers/` から該当ファイルを消して
ワークフローを再実行します。非公開・削除済みの投稿は取得できず、プレースホルダのままになります。

> このワークフローはリポジトリに書き込みます。動かない場合は
> Settings → Actions → General → Workflow permissions が
> **Read and write permissions** になっているか確認してください。

YouTube のサムネイルはこの仕組みを使わず、`i.ytimg.com` から直接読み込んでいます
（CORP が付いていないため）。使っているのは **`oar2.jpg`** で、これは元の縦横比のまま返します
（Shorts なら 1080×1920、通常動画なら 1920×1080）。よく使われる `hqdefault.jpg` は常に
480×360 に letterbox されるため、縦動画だと上下に黒帯が入ってしまいます。

`oar2` は公開されている仕様ではないので、取得できなかった場合は `hqdefault.jpg` に落とします。
なお YouTube はサムネイルの無い動画に対して 404 ではなく **120×90 の灰色画像を 200 で返す**ため、
読み込めたように見えます。サイズで判定して失敗扱いにしています。

### Instagram の埋め込みでは動画は再生できない

**これは実装の制限ではなく Instagram 側の仕様です。** 埋め込みページ（`/embed/captioned/`）の
中身を調べると、動画ファイルへの参照が一切含まれていません。

```
video_url / video_versions / .mp4 / 動画CDNのURL → いずれも 0件
含まれるのは JS・CSS・表紙画像のみ
```

埋め込みに表示される再生ボタンは Instagram 側が置いている導線で、押すと Instagram へ
移動する作りになっています。このギャラリーでは iframe に `sandbox` を付けて
**その移動をブロック**しているため、押しても何も起きません。意図せず Instagram の
リール画面（スワイプで次々おすすめが流れてくる画面）に飛ばされることはありません。

つまり **Instagram の投稿は「表紙とキャプションの索引」として機能し、再生はできません。**
実際に再生したいなら、次の「動画ファイルを登録する」を使ってください。

YouTube と Vimeo は埋め込み内で普通に再生できます。制約は Instagram 固有のものです。

### 自分の動画を公開する場合は YouTube 経由が楽

自作の MV などを「動画として再生できる形で」公開したいなら、YouTube に上げて URL を登録する
のが最も手間が少ない方法です。

| | リポジトリに直接置く | YouTube に上げる |
|---|---|---|
| ファイルサイズ | **100MB まで**（GitHub の制限） | 256GB / 12時間まで |
| 圧縮 | 必須（1080p60 の MV は 200MB 超える） | 不要。書き出したまま上げられる |
| 変換・配信 | なし。元ファイルをそのまま配る | 画質自動生成・CDN 配信つき |
| 履歴 | 消せない。リポジトリが永久に重くなる | いつでも削除・非公開にできる |
| 費用 | 帯域を使う | 無料 |

**縦 1080×1920 で 3分以内の動画は、YouTube 側で自動的に Shorts 扱いになります。** この
ギャラリーのカードは 9:16 なので、そのままぴったり収まります。

- 「限定公開」でも埋め込み再生はできます。YouTube の検索や一覧には出したくないが、
  ギャラリーからは見せたい、という場合はこちらを選んでください
- カバー画像は自動取得されます（Instagram と違い Actions は不要）。
  縦動画なら縦のまま、横動画なら横のまま取得します
- 埋め込みには `rel=0` を付けているので、再生後のおすすめは同一チャンネル内に限定されます

登録手順は、YouTube に上げて URL をコピーし、フォームの「元の投稿 URL」に貼るだけです。
`youtu.be/...`・`watch?v=...`・`/shorts/...` のいずれの形式でも認識します。

### 動画ファイルを登録する（自分の動画向け）

追加フォームの「動画ファイル」で **端末から選ぶ** を押すと、動画がリポジトリの `media/` に
コミットされ、そのパスが自動で入ります。以降はページ内で直接再生されます。

- GitHub 連携の設定が前提です（トークンを使ってアップロードするため）
- 25MB を超えると確認、**60MB を超えると拒否**します
- **一度コミットした動画は Git の履歴から消せません。** リポジトリは永久に重くなります。
  不要になったファイルを消しても、履歴には残り続けます
- GitHub Pages にはソフト上限（サイト 1GB、帯域 月100GB）があります
- 動画の縦横比は読み込み時に実測され、カードがその比率に合わせて調整されます
- 外部のホスティング先に置いた動画の URL を直接書いても構いません

**他人の投稿の動画を保存して再生する用途には使わないでください。** 権利上の問題があります。
自分が撮影・投稿した動画を対象とした機能です。

## 対応プラットフォーム

| | 埋め込み | サムネイル自動取得 |
|---|---|---|
| Instagram（`/p/`・`/reel/`・`/tv/`） | 表紙のみ（**動画は再生不可**） | ○（Actions 経由） |
| YouTube（通常・`youtu.be`・Shorts） | ○ | ○ |
| TikTok | ○ | × |
| Vimeo | ○ | × |
| X / Twitter | ×（リンクカードとして表示） | × |
| その他の URL | ×（リンクカードとして表示） | × |

Instagram は **公開アカウントの投稿のみ** 埋め込めます。非公開アカウントや削除済みの投稿は
「投稿が削除された可能性があります」と表示されます。

サムネイルが自動取得できないプラットフォームは、グラデーションのプレースホルダになります。
気になる場合はフォームの「サムネイル URL」に任意の画像 URL を入れてください。

> 投稿のタイトルや本文を自動取得することはしていません。Instagram の oEmbed API は
> アクセストークンが必要で、静的サイトからは呼べないためです。タイトルは手入力です。

## データの持ち方

保存先は 2 か所あり、役割が違います。

| | 場所 | 見える範囲 |
|---|---|---|
| 編集中のデータ | ブラウザの localStorage | 自分のそのブラウザだけ |
| 公開データ | `data/videos.json` | サイトを見た全員 |

初回アクセス時に `data/videos.json` を読み込んで localStorage に取り込み、以降はブラウザ側を
正としています。この 2 つを繋ぐ方法が 2 通りあります。

### A. GitHub 連携（推奨）— アプリから直接コミットする

メニュー →「**GitHub 連携の設定**」でトークンを登録すると、以降は**追加・編集・削除・並び替えが
そのまま `data/videos.json` にコミット**されます。書き出し作業は不要で、スマホからも操作できます。

**トークンの作り方**

GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token

| 項目 | 設定 |
|---|---|
| Repository access | **Only select repositories** → 公開用リポジトリ 1 つだけ |
| Permissions → Repository permissions → **Contents** | **Read and write** |
| Expiration | 期限を設定する（無期限にしない） |

生成された `github_pat_...` をアプリの設定画面に貼るだけです。

**動作**

- 編集すると 2.5 秒後にまとめて 1 コミットされる（連打してもコミットは荒れない）
- ヘッダーのバッジで状態が分かる：`✓ 同期済み` / `● 未反映` / `⟳ 反映中` / `! 要確認`
- バッジを押すと即時反映。失敗時はバッジから設定画面を開いて原因を確認できる
- 未反映のまま閉じようとすると警告が出る。閉じても次回起動時に自動で送られる
- 別の端末から編集されていた場合は**上書きせずに停止**し、「GitHub 側を取り込む」か
  「この端末の内容で上書き」を選ばせる
- コミットが Pages に反映されるまで数十秒かかる（API 経由の読み込みは即時）

**セキュリティ上の注意**

- トークンは **localStorage にのみ**保存されます。リポジトリにも、書き出す JSON にも含まれません。
- localStorage は暗号化されていません。**共有 PC では連携しない**でください。
- 権限を上記の通り絞れば、漏れた場合の影響はそのリポジトリのファイル書き換えだけに限定されます。
- 使わなくなったら設定画面の「**連携を解除**」でトークンを削除し、GitHub 側でも revoke してください。
- 公開サイトのデータ自体は誰でも読めます。トークンで守られるのは**書き込みだけ**です。

### B. 手動 — 書き出して差し替える

トークンを使いたくない場合。

1. ページ上で追加・編集・並び替えを行う
2. メニュー →「**JSON を書き出し**」で `videos.json` をダウンロード
3. リポジトリの `data/videos.json` を差し替えて commit / push

GitHub の Web エディタで直接貼り付けたい場合は「**JSON をクリップボードにコピー**」を使う。

自分のブラウザのデータを公開データに戻したいときは、メニュー →「公開データを再読み込み」。

### `data/videos.json` の形式

```json
{
  "version": 1,
  "items": [
    {
      "id": "v1a2b3c4d",
      "url": "https://www.instagram.com/reel/XXXXXXXXX/",
      "platform": "instagram",
      "title": "夏の海リール",
      "description": "説明文。改行もそのまま表示される。",
      "tags": ["旅行", "海"],
      "thumbnail": "",
      "favorite": true,
      "rating": 5,
      "publishedAt": "2026-07-01",
      "createdAt": "2026-08-13T09:00:00.000Z",
      "updatedAt": "2026-08-13T09:00:00.000Z",
      "order": 0
    }
  ]
}
```

`url` 以外は省略可（読み込み時に補完される）。`order` が手動並び替えの順序。
手で書く場合は `platform` も省略してよく、`url` から判定される。

## GitHub Pages で公開する

このリポジトリは非公開の複数プロジェクト置き場なので、公開用は**別リポジトリに切り出す**のが安全。
（GitHub Pages の公開元に指定できるのはリポジトリ直下か `/docs` だけで、
`web-site-test/video-gallery/` のような深い階層は指定できない。）

```bash
cd web-site-test/video-gallery
git init
git add .
git commit -m "動画ギャラリーの初期公開"
gh repo create video-gallery --public --source=. --push
```

作成後、GitHub の Settings → Pages で Source を `main` / `/ (root)` に設定する。
数分後に `https://<ユーザー名>.github.io/video-gallery/` で公開される。

公開後は、そのサイトを開いて GitHub 連携を設定すれば以降の更新はアプリ内で完結する。
（公開 URL が `*.github.io` の場合、設定画面のオーナーとリポジトリは URL から自動入力される。）

> `.nojekyll` を置いてあるので、Jekyll による処理はスキップされる。

## 注意点

- **`sw.js` の `CACHE_NAME` は、静的ファイルを編集したら必ず上げること。**
  上げないと Service Worker が古いファイルを配信し続け、変更が反映されていないように見える。
- `[hidden]` を効かせるために `style.css` の冒頭で `[hidden] { display: none !important }` を
  指定している。`.toast` や `.gallery` などに `display` を直接指定しているため、これがないと
  `hidden` 属性が無視される。
- `.toolbar` は `backdrop-filter` を持つので、その中に `position: fixed` の要素を置くと
  ビューポートではなくツールバー基準で配置されてしまう。モバイル用の追加ボタン（`.fab`）を
  `<body>` 直下に置いているのはこのため。
- `file://` で直接開くと `data/videos.json` の fetch が失敗する（空で起動する）。
  ローカル確認は必ず HTTP サーバー経由で。
- GitHub の Contents API が返す base64 は 60 文字ごとに改行が入っている。`atob` に渡す前に
  空白を除去しないと日本語が壊れる。また `btoa` は Latin-1 しか扱えないので、送信側は
  `TextEncoder` でバイト列にしてから base64 化している（`toBase64` / `fromBase64`）。
- Contents API で読めるのは 1MB までのファイル。動画数千件で到達する規模ではないが、
  超えるとエラーメッセージを出して停止する。
- 埋め込み iframe には `sandbox` を付けている（`allow-top-navigation` と `allow-popups` を
  与えていない）。これにより埋め込み側がギャラリーを離れて Instagram 等へ遷移させることを
  防いでいる。`allow-scripts` と `allow-same-origin` を外すと埋め込み自体が表示されなくなる。
- アップロードした動画のファイル名は ASCII に正規化している。日本語のファイル名をそのまま
  使うと URL・Git・Pages のそれぞれで扱いが面倒になるため。元のファイル名はタイトルの
  初期値として使われる。
